L# LDocumentation & Communication Rules
L
L## LDocumentation Philosophy
L- **Living documentation**: Documentation that evolves with the codebase
L- **Audience awareness**: Write for the appropriate audience level
L- **Practical focus**: Focus on actionable information
L- **Maintenance commitment**: Keep documentation current and accurate
L
L## LCode Documentation
L### LInline Documentation
L- **Why over what**: Explain why code exists, not just what it does
L- **Complex logic**: Document complex algorithms and business logic
L- **Assumptions**: Document key assumptions and constraints
L- **Edge cases**: Document handling of edge cases and error conditions
L
L### LFunction Documentation
L- **JSDoc comments**: Use JSDoc for public API functions
L- **Parameter descriptions**: Document all parameters and their types
L- **Return values**: Document return values and possible errors
L- **Usage examples**: Include usage examples for complex functions
L
L## LAPI Documentation
L### LREST API Documentation
L- **Endpoint descriptions**: Clearly describe what each endpoint does
L- **Request/response formats**: Document request and response schemas
L- **Authentication**: Document authentication requirements
L- **Error responses**: Document all possible error responses
L
L### LComponent Documentation
L- **Props documentation**: Document all component props
L- **Usage examples**: Provide usage examples for components
L- **Styling notes**: Document styling requirements or considerations
L- **Accessibility**: Document accessibility features and requirements
L
L## LProject Documentation
L### LREADME Files
L- **Project overview**: Clear description of what the project does
L- **Setup instructions**: Step-by-step setup and installation
L- **Usage examples**: Basic usage examples and getting started
L- **Contributing guidelines**: How to contribute to the project
L
L### LArchitecture Documentation
L- **System overview**: High-level system architecture
L- **Component relationships**: How components interact
L- **Data flow**: Data flow through the system
L- **Technology choices**: Rationale for technology selections
L
L## LTechnical Writing

L- **Active voice**: Use active voice for clarity

L### LFormatting Standards

L- **Link organization**: Organize links logically
